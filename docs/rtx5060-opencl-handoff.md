# NVIDIA OpenCL evidence for the GPU deep dive

Prepared on Arch Linux, 2026-10-21, for blog agent session `blog-b4`,
ask A7. Captured with `just opencl-evidence` on `opencl:0`, the
NVIDIA GeForce RTX 5060 Ti (16 GB), driver 615.78.08.

## Text the post can use

The threshold demo lowers to one fused OpenCL C 1.2 kernel, `k0`,
with eight work-items in one group and five output arrays. On the
RTX 5060 Ti all five output lines match the evaluator baseline
byte for byte. The schedule uses f32 for Float and i64 for Int.

Asked for `CL_PROGRAM_BINARIES`, NVIDIA's OpenCL reports an
`executable` program binary of 2,252 bytes. Its contents are PTX
text generated by NVIDIA's NVVM compiler: `.version 9.4`,
`.target sm_120, texmode_independent`, `.address_size 64`, with
entry point `k0`. The raw binary and saved `.ptx` are identical.
The CLI's generic magic classifier calls it `unrecognized`; the
capture script recognizes the PTX directives and saves the text.

This supplies the driver's PTX for the threshold source program
used for the Mojo and nvcc comparisons. It does not establish that
those routes generate identical instructions. PTX is an intermediate
instruction set; this capture contains no cubin or final SASS.

The single captured run reports setup 1091.371 ms, device kernels
0.500 ms, host launches 4.679 ms, total 1112.816 ms. These are
capture observations for eight elements, not a performance claim.

## Limits and reproduction

The run and binary query build the same generated source separately,
with the same empty build options. The capture proves output agreement
and exposes the binary returned by the driver; it does not inspect
the final instructions executed on the GPU. The Apple comparison is
in [the M1 Max handoff](m1max-opencl-handoff.md).

```sh
just build
just opencl-evidence docs/evidence/rtx5060-opencl-20261021-device --device opencl:0
```

The output directory must not already exist. Device access must be
available to the process; the first sandboxed attempt could enumerate
the card but could not run it. The linked capture ran with device access.
